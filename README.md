# Auto Flex

`auto-flex` is a Codex skill that converts a natural-language experiment request into a reviewed Opentrons Flex protocol, or accepts an existing Python protocol and sends it directly through documentation, simulation, repair, and optional live execution. It uses the Opentrons MCP server for robot communication.

## What it includes

- A 30-second Windows plan-review dialog with confirm, revision feedback, and timeout auto-confirm.
- A bundled Flex Python API reference and a local BM25 RAG index; no embedding service or API key is required.
- Deterministic experiment folders such as `2026-09-23_exp01`.
- Simulation logging and a bounded repair loop.
- Live Flex upload, execution, and status monitoring through the `opentrons` MCP server.
- A fast path for supplied `*.py` protocols: generate a detailed experiment introduction, preserve the original file, and go directly to simulation and execution.
- A separate explicit confirmation before any real robot run. The timed plan confirmation never authorizes physical execution.

## Supported environment

- Windows 10 or 11.
- Codex desktop or Codex CLI with personal skills support.
- PowerShell 5.1 or later.
- Git.
- Python 3.11 or 3.12 for the Opentrons simulator.
- Node.js 18 or later plus npm for the Opentrons MCP server.
- An Opentrons Flex reachable from the computer for live execution.

The plan dialog uses WPF and is therefore Windows-specific. RAG indexing and retrieval are pure Python and require no third-party packages.

## 1. Install the skill

Open PowerShell and clone the repository directly into the Codex personal skills directory:

```powershell
$codexRoot = Join-Path ([Environment]::GetFolderPath('UserProfile')) '.codex'
$skillsRoot = Join-Path $codexRoot 'skills'
New-Item -ItemType Directory -Force -Path $skillsRoot | Out-Null
git clone https://github.com/xufana7/auto-flex.git (Join-Path $skillsRoot 'auto-flex')
```

If the folder already exists, update it instead:

```powershell
git -C (Join-Path ([Environment]::GetFolderPath('UserProfile')) '.codex\skills\auto-flex') pull --ff-only
```

Restart Codex after the first installation so that `$auto-flex` appears in the available skills list.

## 2. Build or refresh the local RAG index

The repository includes a prebuilt index, but rebuilding it after changing `Flex_API_Documentation.md` is recommended:

```powershell
$skillRoot = Join-Path ([Environment]::GetFolderPath('UserProfile')) '.codex\skills\auto-flex'
python (Join-Path $skillRoot 'scripts\build_rag_index.py') `
  (Join-Path $skillRoot 'references\Flex_API_Documentation.md') `
  (Join-Path $skillRoot 'references\flex_api_index.json')
```

Test retrieval:

```powershell
python (Join-Path $skillRoot 'scripts\query_flex_docs.py') `
  --index (Join-Path $skillRoot 'references\flex_api_index.json') `
  --top-k 3 `
  'Flex 96 channel pipette load_instrument tip rack transfer'
```

## 3. Install the Opentrons simulator

The setup script creates an isolated virtual environment at `%USERPROFILE%\.codex\venvs\auto-flex` and installs the `opentrons` package there:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File `
  (Join-Path $skillRoot 'scripts\setup_simulator.ps1')
```

If Python discovery fails, pass a Python 3.11 or 3.12 executable explicitly:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File `
  (Join-Path $skillRoot 'scripts\setup_simulator.ps1') `
  -PythonPath 'C:\Path\To\Python312\python.exe'
```

Verify the simulator:

```powershell
& (Join-Path ([Environment]::GetFolderPath('UserProfile')) '.codex\venvs\auto-flex\Scripts\opentrons_simulate.exe') --help
```

## 4. Install and register the Opentrons MCP server

The upstream server is [`yerbymatey/opentrons-mcp`](https://github.com/yerbymatey/opentrons-mcp).

### Recommended npm installation

```powershell
npm install -g opentrons-mcp
codex mcp add opentrons -- opentrons-mcp
```

### Install from source

```powershell
$codexRoot = Join-Path ([Environment]::GetFolderPath('UserProfile')) '.codex'
$mcpRoot = Join-Path $codexRoot 'mcp'
New-Item -ItemType Directory -Force -Path $mcpRoot | Out-Null
git clone https://github.com/yerbymatey/opentrons-mcp.git (Join-Path $mcpRoot 'opentrons-mcp')
npm --prefix (Join-Path $mcpRoot 'opentrons-mcp') ci --omit=dev --ignore-scripts
codex mcp add opentrons -- node (Join-Path $mcpRoot 'opentrons-mcp\index.js')
```

Verify registration:

```powershell
codex mcp get opentrons
codex mcp list
```

### Disable the upstream undocumented recovery tool

The upstream server currently exposes an undocumented `poll_error_endpoint_and_fix` tool containing hard-coded private-network addresses and an Anthropic API call. Disable it in `%USERPROFILE%\.codex\config.toml`:

```toml
[mcp_servers.opentrons]
# Keep the command and args generated by `codex mcp add`.
disabled_tools = ["poll_error_endpoint_and_fix"]
```

Restart Codex after changing MCP configuration.

## 5. Validate the installation

Check that the skill is discoverable by starting a new Codex task and entering:

```text
$auto-flex Create a plan that transfers 100 uL from a source plate to a destination plate and mixes three times. Stop before live execution.
```

Expected behavior:

1. A `YYYY-MM-DD_expNN` directory is created in the active workspace.
2. An `exp_NN.md` plan is generated.
3. A plan-review window shows the plan, accepts revision feedback, and displays a 30-second countdown beside the confirmation button.
4. `protocol_NN.py` is generated only after plan confirmation.
5. Simulation logs are saved as `simulation_NN_attempt_XX.log` until the protocol succeeds or the bounded retry limit is reached.
6. The skill stops before physical execution unless you explicitly confirm the robot IP and protocol file.

### Validate the existing-protocol route

Pass an absolute protocol path or attach a `.py` file:

```text
$auto-flex Use C:\Protocols\assay.py. Generate the detailed experiment introduction, simulate and repair the working copy, then prepare to run it on the Flex at 192.168.1.100.
```

Expected behavior:

1. The original protocol is hashed and left unchanged.
2. A working copy is saved as `protocol_NN.py` inside the new experiment directory.
3. `exp_NN.md` documents the experiment in detail from the request and protocol source.
4. The plan-review dialog and protocol-generation step are skipped.
5. Simulation and repair begin immediately on the working copy.
6. Live execution still requires a separate explicit confirmation immediately before upload and start.

## Usage

Invoke the skill explicitly:

```text
$auto-flex Prepare a Flex protocol for my described assay. Simulate it, but do not run it on the robot.
```

For live execution, include the robot IP and expect a separate confirmation immediately before upload and start:

```text
$auto-flex Build and simulate this assay for the Flex at 192.168.1.100. After simulation, ask me before running it.
```

For an existing protocol, attach the file or provide its path:

```text
$auto-flex Use D:\Lab\protocols\plate_transfer.py with the Flex at 192.168.1.100. Document the experiment, simulate and repair it, then continue to the live-run confirmation.
```

Generated artifacts remain together:

```text
YYYY-MM-DD_expNN/
  exp_NN.md
  plan_confirmation_NN_attempt_01.json
  protocol_NN.py
  simulation_NN_attempt_01.log
  live_run_NN.log
```

## Uninstalling

1. Close Codex.
2. Remove `%USERPROFILE%\.codex\skills\auto-flex`.
3. Optionally remove `%USERPROFILE%\.codex\venvs\auto-flex`.
4. If the MCP server is no longer needed, run:

   ```powershell
   codex mcp remove opentrons
   npm uninstall -g opentrons-mcp
   ```

## Safety notes

- Review deck layout, labware load names, pipettes, volumes, modules, and well mappings before confirmation.
- Simulation does not validate physical setup, reagent identity, deck calibration, tip availability, or collision risks outside the simulator model.
- Keep the Flex emergency-stop procedure available during live runs.
- Never treat the 30-second plan timeout as permission to move hardware.
